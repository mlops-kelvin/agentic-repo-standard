# Contributing to Agentic Repo Standard

## How to Contribute

This is a living standard. It improves as more teams apply it and report what works.

### What We Accept

- **Proof cases**: Applied the framework to a repo? Document the before/after metrics and what you learned. Mob-speak applies — no identifying details.
- **Phase refinements**: Found a gap in a phase definition? Propose specific changes with rationale.
- **Anti-pattern additions**: Discovered a new failure mode? Document it with the pattern and why it fails.
- **Measurement methods**: Better ways to quantify cognitive debt or transformation progress.
- **Done criteria templates**: Phase-specific checklists from real transformations.

### What We Don't Accept

- Generic refactoring advice without proof case evidence
- Changes that weaken the standard (removing requirements, softening gates)
- Identifying information about specific projects, companies, or people

### Process

1. Open an issue describing the proposed change
2. Reference a proof case or evidence
3. PR with the change
4. Two reviewers approve before merge

### Style

- Prescriptive, not advisory. "Do X" not "consider doing X."
- Concrete, not abstract. Metrics, not feelings.
- Circle speak on all public content — no human names, no company names.
